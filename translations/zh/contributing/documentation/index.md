# 贡献文档

感谢你有兴趣帮助改进 Nix 生态中的文档。

## 入门

先查看 [文档资源](./resources.md) 概览。
文档贡献应遵循 [风格指南](./style-guide.md)。

如需更多指导，请联系 [Nix 文档团队](https://nixos.org/community/teams/documentation)。

:::{important}
如果你无法投入时间，可以考虑 [通过 Open Collective 向 NixOS 基金会的文档项目捐赠](https://opencollective.com/nixos/projects/nix-documentation)，以资助参考文档与学习材料的持续维护与开发。
:::

## 反馈

反馈同样是有价值的贡献。
请在 [Discourse 的 Documentation 分区](https://discourse.nixos.org/c/dev/documentation/25) 分享你的想法。

### Nix 初学者

尽量以官方文档作为主要资源，哪怕它看起来还不完整。

请提交议题，并报告所有遇到的问题或疑问。
也请说明你的学习目标，以及目前走过的路径。

分享第一手经验，有助于我们为你和所有人解决文档中反复出现的问题。

### Nix 教育者

你可能已经观察到学习者最常卡在哪里，以及他们有哪些典型需求与问题。
你可能也有自己的课堂、培训或演讲笔记。

请分享你的经验，帮助我们改进上游文档与入门材料，让你能把精力放在给学生创造最大价值上。

### 在特定领域使用 Nix 的专家

如果你擅长把 Nix 应用到某个领域问题，并希望分享最佳实践，请先查看已有内容。
- 关于你主题的现有材料是否达到你的标准？
- 我们该如何改进？
- 是否有尚未覆盖、但很流行的 Nix 能力应用？
- 我们很乐意吸收你的洞见。

## 许可与署名

在提交包含你自己贡献的 pull request 时，你同意以 [CC-BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/) 许可你的作品。

添加他人材料时，请确认其许可允许这样做。
此时，应在新增内容中明确标明来源、作者与许可。
理想情况下，在使用其作品*之前*通知作者。

[将原作者添加为共同作者](https://docs.github.com/en/pull-requests/committing-changes-to-your-project/creating-and-editing-commits/creating-a-commit-with-multiple-authors) 到 pull request 的第一个提交中，该提交应包含原文原文，以便我们通过版本历史追踪作者与变更。

单个文档也可以使用 CC-BY-SA 4.0 以外的自由许可。
向这些文档贡献变更时，你同意按相应许可授权你的工作。

:::{note}
如果你写过与 Nix 相关的教程或指南，请考虑以 CC-BY-SA 4.0 许可。
这样，若你的作品能补充或改进现有材料，我们就可以将其作为官方文档收录。
:::
